# engine/runtime

The Truffle/GraalVM interpreter for Enso. The **language-side** code (everything
that executes inside the polyglot context). Package root `org.enso.interpreter`.

Read [Runtime-Guide](https://github.com/jdunkerley/enso/wiki/Runtime-Guide)
before making non-trivial changes — it maps entry points, documents threading,
and links the required Graal/Truffle background reading.

## Key classes

- `EnsoLanguage.java` — The `TruffleLanguage` implementation. Entry point for
  everything.
- `EnsoContext.java` — Per-context state (module registry, builtins,
  distribution paths, thread manager).
- `runtime/builtin/Builtins.java` — Synthesizes the `Standard.Builtins` virtual
  module from annotation-processor output. Changing a builtin touches both the
  Java class and the `@BuiltinMethod` annotations that drive codegen.

## Subpackages

- `node/` — Truffle `Node` classes that make up the AST (callable handling,
  control flow, expressions, scopes, type checks).
- `runtime/` — Non-AST runtime helpers: module system, data (atoms, vectors,
  numbers, text, warnings, hash maps, …), builtins, callables, control
  (exceptions, TCO), scope, state, resource management.
- `service/` — Runtime services exposed over `RuntimeServerInstrument` to the
  language server.
- `caches/` — IR/module cache machinery (persisted compilations for faster
  startup).
- `util/` — Shared helpers.

## Non-obvious conventions

- **`public static build(...)`** on every Truffle node used in an AST.
  DSL-generated nodes delegate to the autogenerated `create(...)`. Nodes never
  meant to appear in ASTs (e.g. builtin-function root nodes) expose
  `asFunction()` instead.
- **`InteropLibrary` only** for language-side dispatch. Never import
  `org.graalvm.polyglot`. Never depend on `truffle-api` from outside this tree.
- **`@CompilationFinal` + `final`** — Truffle does constant folding on these.
  Use them aggressively for fields that are set once during compilation /
  initialization. Pair with `@ExplodeLoop` when a loop bound is
  compilation-final.
- **DSL `@Specialization`** — Read generated code before guessing. Subtle bugs
  hide in specialization-ordering and guard interactions.
- **Safepoints.** Every iteration of a TCO loop and every non-inlined method
  call should poll safepoints. See `runtime/ThreadManager.java`.
- **No `System.out.println`.** Use `TruffleLogger` in language code; the
  embedder configures sinks.
- **Service lookup covers installed libraries, not only loaded ones.**
  `Meta.lookup_services` (`LookupServicesNode`) loads a library that is
  installed but not imported when it resolves that library's provider; see Note
  [Service Discovery Over Installed Libraries] there.
- **Compiling a library writes its `catalogue.json`.** Next to `package.yaml`,
  from the suggestions cache's list, filtered to what the component browser
  shows; see Note [Library Catalogue] in `TruffleCompilerContext`.
- **Library caches are keyed by the library's sources.** The bindings and
  suggestions caches record `Package.sourceHash`, computed once per library per
  context (`LibrarySourceHashes`), so two checkouts of a library with the same
  name and version share them only when their sources match; see Note [Library
  Caches Are Keyed By The Sources]. A module's IR cache stays keyed by its own
  source and the names of the modules in its directory (Note [A Cached Module
  Follows Its Directory] in `ModuleCache`); a cached module whose same-library
  import changed is recompiled (Note [A Cached Module Follows Its Library's
  Imports] in `Compiler`).
- **IR caches record the other libraries they refer to.** A module's IR cache
  and a library's bindings cache record the source hash of every other library
  their IR names, and the modules it names there and in its own library, and
  miss when one changed or a module is gone (Note [A Cache Records The Libraries
  It Refers To] in `LibraryDependencies`). A cache that fails to deserialise is
  deleted and is a miss, with a warning in the log (Note [A Cache That Does Not
  Load Is A Miss] in `Cache`).
- **A rejected bindings cache is rewritten into the user cache.** When a run
  rejects a library's bindings cache (its sources or a dependency's changed), it
  writes a new one, from the modules it compiled, next to the library's
  per-module IR caches; reads try the library's own location first, then the
  user cache (Note [A Rejected Bindings Cache Is Rewritten] in
  `TruffleCompilerContext`). Only `enso --compile` writes the library's own
  location. Exit does not wait for the rewrite. Every cache file is written to a
  temporary file and renamed into place (Note [A Cache Is Written By Renaming]
  in `Cache`).
- **A library's bindings cache is read once per context**, by
  `TruffleCompilerContext.libraryBindings`, which import resolution and module
  loading share; see Note [One Bindings Cache Read Per Library].
- **Some library failures are remembered, and only an import's are reported.**
  `DefaultPackageRepository` keeps a failed download, and a library the edition
  does not define (unless the project prefers local libraries), until
  `shutdown`, so later imports neither resolve nor download it again. A missing
  local library or one that failed to load from disk is tried again. Only a
  failure an import meets (`ensurePackageIsLoadedForImport`) goes to
  `NotificationHandler.libraryLoadFailed` (in the IDE, `Api.LibraryLoadFailed`
  to the language server), once per library and failure. See Note [A Failed
  Library Is Remembered].

## Language Server integration

The `RuntimeServerInstrument` (under `runtime-instrument-runtime-server/`, not
here) attaches to this runtime. Messages flow over `polyglot-api` types using a
stringly-typed method-name convention — chase those constants to cross the
embedder/language boundary.

## Tests

Ultimately driven from SBT (`runtime-integration-tests/test`). Scalatest + Enso
stdlib tests that exercise the whole compiler + runtime. Don't add Java-side
mocks for runtime behavior — tests should go through a live context.

## JNI native parser

At startup, `EnsoContext` loads `enso_parser` (the JNI `cdylib` from
`lib/rust/parser/jni/`). Make sure the library is on `java.library.path` or
inside the engine distribution under `component/runtime/`.
